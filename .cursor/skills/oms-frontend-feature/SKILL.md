# OMS Frontend Feature

Stack: React 19, TanStack Router (file routes in `frontend/src/routes/_layout/`), TanStack Query, TanStack Table, shadcn/ui (`frontend/src/components/ui/`), react-hook-form + zod, Biome, Playwright. API access goes only through the generated client in `frontend/src/client/`.

## Steps

1. **Regenerate the client** after any backend schema/route change:

   ```bash
   bash ./scripts/generate-client.sh   # or: cd frontend && bun run generate-client (backend must be running)
   ```

   Never hand-write API types or edit `frontend/src/client/*.gen.ts`.

2. **Route**: create `frontend/src/routes/_layout/<page>.tsx` with `createFileRoute`, following `items.tsx`:
   - a `get<Thing>QueryOptions()` returning `{ queryFn, queryKey }`;
   - `useSuspenseQuery` inside a `<Suspense>` with a pending skeleton;
   - an empty state;
   - `<DataTable columns={columns} data={...} />` from `@/components/Common/DataTable`.
   The route tree (`routeTree.gen.ts`) is regenerated by the Vite plugin; do not edit it by hand.

3. **Components** in `frontend/src/components/<Domain>/`: `columns.tsx`, `Add<Thing>.tsx`, `Edit<Thing>.tsx`, `<Thing>ActionsMenu.tsx`. Use dialogs for forms, `useMutation` + `queryClient.invalidateQueries({ queryKey })` on success, and `sonner` toasts via the existing `useCustomToast` hook.

4. **Forms**: zod schema + `zodResolver`; mirror backend limits, but treat the backend as authoritative and surface its 4xx `detail` messages.

5. **Navigation**: add the page to `frontend/src/components/Sidebar/AppSidebar.tsx`, shown only for roles that have the permission.

6. **Add shadcn components** with the shadcn MCP or `bunx shadcn@latest add <component>`.

## OMS UI rules

- Format money with a shared VND formatter (`Intl.NumberFormat("vi-VN", { style: "currency", currency: "VND" })`); never format ad hoc.
- Show dates in the business timezone from settings.
- Never compute authoritative totals, costs, or stock on the client. POS may show a preview, but the displayed total after save comes from the API response.
- Send an `Idempotency-Key` (`crypto.randomUUID()` generated once per user action) on complete/pay/refund/post/adjust mutations, and disable the button while pending.
- Confirm destructive or financially significant actions (cancel, refund, reverse, post) with a dialog.
- Posted documents show `Reverse`, not `Delete`.
- POS screens must work on tablet widths (>= 768px) with large touch targets.

## Verify

- `cd frontend && bun run lint` and `bun run build`.
- Add/extend a Playwright spec in `frontend/tests/` (`oms-testing` skill).
- For manual checks use the browser tool against `http://localhost:5173`.
